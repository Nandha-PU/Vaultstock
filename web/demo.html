How VaultStock Works — Architectural Overview

1. Calculated Balances (3NF/BCNF)

Traditional databases update a mutable stock column (UPDATE products SET stock = stock - 5), causing race conditions and lost forensic history. VaultStock derives balance dynamically via SUM(IN) - SUM(OUT).

Benefit: Prevents balance desynchronization permanently.

2. Storage-Layer Immutability

Every inventory entry and product is permanent. SQLite triggers (prevent_movement_update and prevent_movement_delete) halt any UPDATE or DELETE at the database engine layer.

Benefit: Defense-in-depth against SQL injection and application bugs.

3. Concurrency & Overdraft Guard

Before any Stock Out transaction is inserted, SQLite trigger prevent_negative_stock computes live stock and immediately aborts if balance < quantity.

Benefit: Overdrafts are mathematically impossible.

4. Cryptographic HMAC-SHA256 Seals

Every operational transaction appends an audit block chained with prev_hash and signed with an external secret HMAC key stored outside the database file.

Benefit: Attackers with raw disk access cannot forge valid signatures.

5. Out-of-Band Head Anchor

On every transaction, the latest block head is mirrored to an independent checkpoint file (data/audit_head.json) outside SQLite.

Benefit: Defeats tail-truncation attacks (deleting the newest records).

6. Continuous Automatic Verification

Verification runs automatically across all 5 dimensions: sequence contiguity, prev_hash linkage, HMAC integrity, relational reconciliation, and external anchor match.

Benefit: Real-time detection without manual auditing overhead.

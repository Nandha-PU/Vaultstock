Data Request Flow & Defense-in-Depth Architecture

End-to-end execution pipeline showing how every inventory request is validated, locked, constrained by SQLite triggers, and sealed into the HMAC ledger
6-STAGE PIPELINE
STAGE 01 API GATEWAY

Request & RBAC Gate

FastAPI verifies HS256 JWT session & role (admin vs staff), while Pydantic v2 sanitizes inputs and enforces strict bounds.

Blocks: Unauthenticated access, SQLi/XSS payloads, NaN/Inf overflow
→
STAGE 02 CONCURRENCY

Immediate Write Lock

SQLite runs in WAL journal mode and opens writes with BEGIN IMMEDIATE to serialize concurrent check-then-act operations.

Blocks: Lost-update race conditions & concurrent double-spend dispatches
→
STAGE 03 3NF SCHEMA

Relational Constraints

Enforces PRAGMA foreign_keys = ON with ON DELETE RESTRICT across categories, suppliers, locations, and products.

Blocks: Orphaned movements, invalid foreign keys, & negative quantities
→
STAGE 04 KERNEL TRIGGERS

Storage-Layer Guards

BEFORE INSERT checks SUM(IN)-SUM(OUT) >= qty; BEFORE UPDATE/DELETE triggers abort edits on movements & audit_log.

Blocks: Stock overdrafts (global & per-warehouse) and historical record erasure
→
STAGE 05 CRYPTO LEDGER

HMAC Chain & Anchor

Signs canonical JSON payload + prev_hash with secret HMAC-SHA256 key and syncs head hash to data/audit_head.json.

Blocks: Direct disk tampering, forged SHA-256 hashes, & tail truncation
→
STAGE 06 READ VIEWS

Dynamic 3NF Views

v_inventory_summary & v_location_inventory derive live stock balances on the fly with zero mutable counter columns.

Guarantees: 100% mathematical reconciliation between ledger and stock
